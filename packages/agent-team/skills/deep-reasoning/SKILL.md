# Deep Reasoning via Sequential Thinking MCP

Задача нетривиальная и требует структурированного разбора — фиксируй шаги ВНЕШНЕ (через tool),
а не «в голове»: их можно ревизовать и ветвить.

## Обязательный протокол

1. **Подтверди задачу** — 1-2 строки: что именно разбираешь.
2. **Вызови `sequentialthinking_sequentialthinking` минимум 5 раз**, в первом `totalThoughts >= 5`:
   - Шаг 1 — Frame: что дано, ограничения, критерии оценки.
   - Шаг 2 — Facts: известно из кода/доков/контекста (с указанием источника).
   - Шаг 3 — Options: 2-4 жизнеспособных варианта (не соломенные).
   - Шаг 4 — Evaluation: каждый вариант по критериям шага 1.
   - Шаг 5 — Decision: рекомендация + явно отвергнутые + триггер пересмотра.
3. Пропустил фактор по ходу — `isRevision: true, revisesThought: K` (какой шаг пересматриваешь).
4. Параллельная альтернатива — `branchFromThought: N, branchId: "<имя>"`.
5. `totalThoughts` оказался мал — `needsMoreThoughts: true`.
6. Финальный вызов — `nextThoughtNeeded: false` с резюме.
7. Только после финального шага — user-facing ответ: решено/почему/отвергнуто/условия пересмотра.

## Качество thought-строк
Каждый thought — реальное содержание: факты, цифры, ссылки на файлы/строки/доки, сравнения по
конкретным критериям, конфликты и допущения. Запрещено: «начинаем анализ», «продолжим», «итак».

## Когда НЕ активировать
Trivial-правки; прямое исполнение; диалоговые ответы; уже утверждённый план перед глазами;
факт-lookup с одним ответом. Экономия: цепочка 5-7 шагов = +1-3k токенов намеренно.
Если задача оказалась проще — заверши цепочку раньше через `nextThoughtNeeded: false` с пометкой
в thought, почему хватило меньшего числа шагов.
